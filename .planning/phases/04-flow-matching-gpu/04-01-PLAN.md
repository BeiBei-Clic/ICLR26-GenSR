对 train_fm.py 做以下修改，保持单卡运行时行为完全不变：

**1. batch_size 按 world_size 切分（在 main 函数中，init_distributed_mode 之后）**

在 `params.device` 设置完成之后、wandb.init 之前，添加：
```python
if params.multi_gpu:
    assert params.batch_size % params.world_size == 0, \
        f"batch_size ({params.batch_size}) must be divisible by world_size ({params.world_size})"
    params.batch_size = params.batch_size // params.world_size
```

**2. DDP 包装 flow_matching 模型**

在 `fm_optimizer = get_optimizer(...)` 之后、`trainer = Trainer(...)` 之前，添加 DDP 包装逻辑：

```python
# DDP 包装
fm_module_raw = modules["flow_matching"]  # 保存原始引用，用于保存 state_dict
if params.multi_gpu:
    from torch.nn.parallel import DistributedDataParallel as DDP
    modules["flow_matching"] = DDP(
        modules["flow_matching"],
        device_ids=[params.local_rank],
        output_device=params.local_rank,
    )
```

注意：不需要 `find_unused_parameters=True`，因为 FM 网络的所有参数都会被使用。

**3. 修改 save_fm_checkpoint 函数，去掉 DDP 的 module. 前缀**

修改 `save_fm_checkpoint` 函数，使用 `fm_module_raw`（原始未包装的模型）保存 state_dict。具体做法：将函数签名改为接受额外的 `fm_module_raw` 参数：

```python
def save_fm_checkpoint(modules, fm_optimizer, epoch, loss, path, fm_module_raw=None):
    fm_state = fm_module_raw.state_dict() if fm_module_raw is not None else modules["flow_matching"].state_dict()
    data = {
        "flow_matching": fm_state,
        ...
    }
    ...
```

所有调用 `save_fm_checkpoint` 的地方需要传入 `fm_module_raw=fm_module_raw`（定义在 main 中）。

**4. 只在 master 进程打印日志、保存 checkpoint、写 wandb**

**5. 梯度累积与 no_sync 配合**

当前训练循环是简单的 `zero_grad → backward → step`，没有使用 `params.accumulate_gradients`。需要添加梯度累积支持以与现有参数保持一致：

将训练循环的内层改为：
```python
fm_net_ddp = modules["flow_matching"]

for step in range(params.n_steps_per_epoch):
    # 梯度累积：仅在第一个累积步同步，其余步用 no_sync 跳过 all-reduce
    is_sync_step = (step + 1) % params.accumulate_gradients == 0
    if params.multi_gpu and not is_sync_step:
        context = fm_net_ddp.no_sync()
    else:
        from contextlib import nullcontext
        context = nullcontext()

    with context:
        fm_loss = trainer.fm_train_step(task)
        if params.accumulate_gradients > 1:
            fm_loss = fm_loss / params.accumulate_gradients
        fm_loss.backward()

    if is_sync_step:
        fm_optimizer.step()
        fm_optimizer.zero_grad()

    epoch_loss += fm_loss.item() * params.accumulate_gradients  # 恢复原始 loss 值
    n_steps += 1

    if params.is_master and (step + 1) % params.print_freq == 0:
        avg_loss = epoch_loss / n_steps
        print(f"  Epoch {epoch} Step {step+1}/{params.n_steps_per_epoch}  "
              f"FM loss: {fm_loss.item() * params.accumulate_gradients:.6f}  avg: {avg_loss:.6f}")
```

在循环末尾，如果最后一步不是 sync step，需要额外做一次 optimizer.step()：
```python
# 处理尾部不完整的累积步
if params.n_steps_per_epoch % params.accumulate_gradients != 0:
    fm_optimizer.step()
    fm_optimizer.zero_grad()
```

**6. 保持单卡行为不变**

所有新增逻辑都通过 `if params.multi_gpu:` 或 `if params.is_master:` 守卫，单卡（world_size=1）时 multi_gpu=False，所有 DDP 分支都不会进入。`accumulate_gradients=1` 时 `no_sync` 不生效，`nullcontext` 不做任何事。

**注意事项：**
- `fm_module_raw` 变量需要在 main 函数中 DDP 包装之前定义，然后在所有 save_fm_checkpoint 调用中传入
- `from contextlib import nullcontext` 放在文件顶部导入
- 不需要修改 trainer_vae.py 中的 fm_train_step，因为它通过 `self.modules["flow_matching"]` 访问模型，DDP 包装后已经是 DDP 对象，forward 调用会自动同步

新的脚本内容：

```bash
#!/bin/bash

set -euo pipefail

# GPU 数量，默认单卡。使用方式: N_GPU=2 bash scripts/train_fm.sh
N_GPU=${N_GPU:-1}

CUDA_VISIBLE_DEVICES=0,1 torchrun \
    --standalone \
    --nproc_per_node=$N_GPU \
    ./train_fm.py \
    --cvae_checkpoint weights/checkpoint.pth \
    --max_input_dimension 10 \
    --batch_size 64 \
    --accumulate_gradients 2 \
    --amp 0 \
    --dump_path ./dump \
    --exp_name fm \
    --exp_id run-fm \
    --latent_dim 512 \
    --d_model 512 \
    --d_input 512 \
    --enc_emb_dim 512 \
    --dec_emb_dim 512 \
    --n_enc_layers 8 \
    --n_dec_layers 16 \
    --n_enc_heads 16 \
    --n_dec_heads 16 \
    --n_steps_per_epoch 2000 \
    --max_epoch 1 \
    --kl_limits 1.0 \
    --model_type vae \
    --lr 1e-3 \
    --fm_lr 1e-4 \
    --fm_epochs 50 \
    --fm_hidden_dim 1024 \
    --fm_n_layers 6 \
    --fm_n_samples 16 \
    --fm_ode_steps 10 \
    --fm_save_periodic 5 \
    --print_freq 100 \
    --save_periodic 25 \
    --wandb_project "symbolic-regression-training" \
    --wandb_group_name "fm-training" \
    --wandb_run_name "fm-stage2"
```

关键改动：
- 用 `torchrun --standalone --nproc_per_node=$N_GPU` 替换 `python`
- `--standalone` 表示单节点模式，不需要外部协调
- N_GPU 默认为 1，单卡时 torchrun 行为等同于 python
- CUDA_VISIBLE_DEVICES=0,1 预设两卡，用户可按需修改
- `N_GPU=2 bash scripts/train_fm.sh` 即可双卡训练
- batch_size=64 会被 train_fm.py 自动按 world_size 切分（双卡时每卡 32）
