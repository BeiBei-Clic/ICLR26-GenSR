1. 创建 `symbolicregression/envs/cython_eval.pyx`，实现栈式求值器。

文件头部编译器指令：
```
# cython: boundscheck=False, wraparound=False, cdivision=True
```

导入：`cimport numpy as np`、`import numpy as np`、`from libc.math cimport sin, cos, exp, log, sqrt, fabs, NAN`

定义 16 个 cdef int 操作码常量：
OP_CONST=0, OP_VAR=1, OP_ADD=2, OP_SUB=3, OP_MUL=4, OP_DIV=5, OP_SIN=6, OP_COS=7, OP_EXP=8, OP_LOG=9, OP_SQRT=10, OP_ABS=11, OP_POW2=12, OP_POW3=13, OP_INV=14, OP_NEG=15

实现 `eval_tree_flat` 函数签名：
```python
def eval_tree_flat(double[:, ::1] x, int[:] opcodes, double[:] constants, int[:] var_dims):
```
注意 x 使用 `double[:, ::1]` 明确要求 C-contiguous。

函数体逻辑：
- `cdef int n = x.shape[0]`（样本数）
- `cdef int n_instr = opcodes.shape[0]`（指令数）
- `cdef int n_stack = 0, const_idx = 0, var_idx = 0`
- `cdef np.ndarray[np.float64_t, ndim=2] stack_arr = np.empty((n_instr, n), dtype=np.float64)` -- 栈空间
- `cdef double[:, ::1] sv = stack_arr`
- `cdef int i, j, op, dim`
- `cdef double val`

主循环 `for i in range(n_instr):`，对每个操作码：
- OP_CONST: val = constants[const_idx]; const_idx += 1; 对 j 循环 sv[n_stack, j] = val; n_stack += 1
- OP_VAR: dim = var_dims[var_idx]; var_idx += 1; 对 j 循环 sv[n_stack, j] = x[j, dim]; n_stack += 1
- OP_ADD: n_stack -= 1; 对 j 循环 sv[n_stack-1, j] += sv[n_stack, j]
- OP_SUB: n_stack -= 1; 对 j 循环 sv[n_stack-1, j] -= sv[n_stack, j]
- OP_MUL: n_stack -= 1; 对 j 循环做乘法 val = sv[n_stack-1, j] * sv[n_stack, j]; sv[n_stack-1, j] = val（cdivision=True 下 NaN 自然传播，无需 try-except）
- OP_DIV: n_stack -= 1; 对 j 循环做除法 val = sv[n_stack-1, j] / sv[n_stack, j]; sv[n_stack-1, j] = val（0/0 产生 NaN by C99，与 Python 中先设 NaN 再除一致）
- OP_SIN: 对 j 循环 sv[n_stack-1, j] = sin(sv[n_stack-1, j])
- OP_COS: 对 j 循环 sv[n_stack-1, j] = cos(sv[n_stack-1, j])
- OP_EXP: 对 j 循环 sv[n_stack-1, j] = exp(sv[n_stack-1, j])
- OP_LOG: 对 j 循环：val = sv[n_stack-1, j]; 如果 val <= 0 则 sv[n_stack-1, j] = NAN，否则 sv[n_stack-1, j] = log(val)
- OP_SQRT: 对 j 循环：val = sv[n_stack-1, j]; 如果 val < 0 则 sv[n_stack-1, j] = NAN，否则 sv[n_stack-1, j] = sqrt(val)
- OP_ABS: 对 j 循环 sv[n_stack-1, j] = fabs(sv[n_stack-1, j])
- OP_POW2: 对 j 循环 val = sv[n_stack-1, j]; sv[n_stack-1, j] = val * val
- OP_POW3: 对 j 循环 val = sv[n_stack-1, j]; sv[n_stack-1, j] = val * val * val
- OP_INV: 对 j 循环 val = sv[n_stack-1, j]; 如果 val == 0 则 sv[n_stack-1, j] = NAN，否则 sv[n_stack-1, j] = 1.0 / val
- OP_NEG: 对 j 循环 sv[n_stack-1, j] = -sv[n_stack-1, j]

最后提取结果：
```python
cdef np.ndarray[np.float64_t, ndim=1] result = np.empty(n, dtype=np.float64)
for j in range(n): result[j] = sv[0, j]
return result
```

测试需要先定义 Python 端的编译函数 `compile_tree`（在测试文件中内联，不在 generators.py 中，这个留给 Plan 02 集成时做）：
```python
OP_CONST, OP_VAR, OP_ADD, OP_SUB, OP_MUL, OP_DIV = 0, 1, 2, 3, 4, 5
OP_SIN, OP_COS, OP_EXP, OP_LOG, OP_SQRT = 6, 7, 8, 9, 10
OP_ABS, OP_POW2, OP_POW3, OP_INV, OP_NEG = 11, 12, 13, 14, 15

OP_MAP = {
    'add': OP_ADD, 'sub': OP_SUB, 'mul': OP_MUL, 'div': OP_DIV,
    'sin': OP_SIN, 'cos': OP_COS, 'exp': OP_EXP, 'log': OP_LOG,
    'sqrt': OP_SQRT, 'abs': OP_ABS, 'pow2': OP_POW2, 'pow3': OP_POW3,
    'inv': OP_INV,
}
MATH_CONSTANTS = {'e': np.e, 'pi': np.pi, 'euler_gamma': np.euler_gamma}

def compile_tree(node):
    """后序遍历 Node 树，生成 (opcodes, constants, var_dims) 三个列表。"""
    opcodes, constants, var_dims = [], [], []
    for child in node.children:
        oc, co, vd = compile_tree(child)
        opcodes.extend(oc); constants.extend(co); var_dims.extend(vd)
    val = node.value
    if val.startswith('x_'):
        dim = int(val.split('_')[1])
        opcodes.append(OP_VAR)
        var_dims.append(dim)
    elif val in OP_MAP:
        opcodes.append(OP_MAP[val])
    else:
        opcodes.append(OP_CONST)
        if val in MATH_CONSTANTS:
            constants.append(MATH_CONSTANTS[val])
        else:
            constants.append(float(val))
    return opcodes, constants, var_dims
```

测试用例：

**test_correctness_basic**: 手动构造一棵简单的表达式树（例如 `mul(add(x_0, 1.0), sin(x_0))`），用 Node.val() 和 eval_tree_flat 分别计算，assert 结果完全一致（用 np.allclose 允许 1e-12 误差）。

**test_correctness_all_operators**: 对每种操作符构造简单表达式树：
- add: x_0 + x_0
- sub: x_0 - x_0
- mul: x_0 * x_0
- div: x_0 / 2.0
- sin/cos/exp/log/sqrt/abs/pow2/pow3/inv/neg: 各对 x_0 操作
每种操作对比 Node.val() vs eval_tree_flat 结果。

**test_nan_handling**: 构造会产生 NaN 的场景：
- div(x_0, 0.0) -- x_0=1.0，分母为 0
- log(x_0) -- x_0=-1.0
- sqrt(x_0) -- x_0=-1.0
- inv(x_0) -- x_0=0.0
- mul(inf, 0.0) -- 构造 mul(exp(700.0), 0.0) 验证 inf*0=NaN。注意：在 cdivision=True 下 C 标准中 inf*0.0 的结果是 NaN（IEEE 754），Python 的 numpy 也是 NaN。构造方式：exp(700) 产生 inf，然后 mul(inf, 0.0)。具体构造 `mul(exp(x_0), 0.0)`，x_0 输入为 700.0。验证 Node.val() 和 eval_tree_flat 的 NaN 位置完全一致（用 np.isnan 对比）。

**test_nodelist**: 使用 `from symbolicregression.envs.generators import RandomFunctions` 生成随机 NodeList，对比 NodeList.val() 与逐节点 compile + eval_tree_flat 的结果。需要构造一个 params 对象来实例化 RandomFunctions（复用 generators.py 底部的 `__main__` 中的方式，用 get_parser）。

**test_compilation_cache**: 验证同一棵树编译一次、用不同输入求值两次的结果与 Node.val() 一致。这模拟了 generate_datapoints 中 fit + predict 两次调用同一棵树的场景。
