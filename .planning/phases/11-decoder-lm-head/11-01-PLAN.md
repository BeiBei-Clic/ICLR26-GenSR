2. 删除 L200-205 的基于 training loss 的 best checkpoint 保存逻辑（即删除 `loss_val < best_loss` 判断和 `torch.save` 块）

3. 在 optimizer step 之后、日志打印之前（L196 之后），插入验证循环块。验证逻辑内联在训练循环中，不抽取函数。具体：

   a. 判断 `(step + 1) % 50 == 0`（per D-02，每50步验证一次）

   b. `decoder.eval()` 切换到 eval 模式

   c. 用 `torch.no_grad()` 包裹整个验证块

   d. 验证数据生成：复制 L119-153 的数据生成逻辑，但把 `gen_expr(train=True)` 改为 `gen_expr(train=False)`（per D-01）。变量名改为 val_src_enc_list, val_x2_list, val_len2_list

   e. 验证 CE loss 计算：复制 L155-188 的逐样本 CE loss 逻辑。变量名改为 val_total_loss, val_count。如果 val_count == 0 则跳过本次验证（continue）

   f. 计算 val_loss = val_total_loss / val_count

   g. `decoder.train()` 恢复训练模式（在 no_grad 块外面）

   h. 如果 val_loss < best_val_loss：更新 best_val_loss，保存 decoder.lm_head.state_dict() 到 {output_dir}/lm_head_best.pt，打印 "New best val loss" 消息

   i. 打印 val_loss 和 best_val_loss

4. 日志打印那行（原 L207-208）保留 training loss 打印，但 best 改为 best_val_loss 引用

5. 最终打印（原 L210-211）也改为引用 best_val_loss

注意：
- 验证数据生成的外层已经有 torch.no_grad()（因为 CVAE/DiT/FeatureFusion 都冻结），所以验证块不需要额外处理梯度
